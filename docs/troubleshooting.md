# Troubleshooting

Common issues and their actual behavior in the current implementation. Error strings below are the safe, display-only messages the extension shows.

## Setup and installation

### "Load unpacked" rejects the directory

- Make sure you selected the **build output** directory (`dist/chromium` or `dist/firefox`), not the repository root or `src/`.
- If `dist/` is missing, run `npm install && npm run build` first. Both `dist/chromium/manifest.json` and `dist/firefox/manifest.json` are generated by the build.
- If the build's verification step fails, it reports which manifest reference is missing; rebuild from a clean tree (`npm run build` starts by removing `dist/`).

### Firefox removes the extension after restart

Temporary add-ons loaded via `about:debugging` are unloaded when Firefox exits. Reload it with **Load Temporary Add-on…** after restarting Firefox. This is Firefox's rule for unsigned extensions; the manifest declares Firefox 109+ as its minimum.

### Side panel / sidebar does not open

- On Chromium, the side panel API requires Chromium 114+. Older versions cannot provide the panel; the toolbar action then opens the extension fallback tab instead. This is the intended fallback, not a failure.
- On Firefox, open the sidebar from View → Sidebar and select **Open WebUI**.
- If opening the native surface fails for any reason, the extension automatically opens the fallback tab (`src/fallback-tab/index.html`). All features work in the fallback tab.

## Connections

### "Enter a valid connection URL." / "Only HTTP and HTTPS connections are supported."

Connection URLs must be HTTP or HTTPS. Other schemes are rejected. Re-enter the URL including the scheme, for example `https://chat.example.com` or `http://localhost:3000`.

### "Connection URLs must not contain credentials."

URLs with embedded usernames/passwords (`https://user:pass@host`) are rejected. Use a URL without credentials; authentication belongs to the Open WebUI page's own login, which the extension never reads or copies.

### "The connection could not be reached." / "The connection test timed out."

**Test connection** performs a bounded HEAD request (5-second timeout, redirects treated as failures, credentials omitted). Check:

- The server is running and the URL and port are correct.
- Any reverse proxy in front of the server is up.
- The timeout message means the server did not answer within 5 seconds.

Note that a passing reachability test does not authenticate you; the embedded page handles login through its own normal form.

### "Open WebUI could not be embedded"

The panel could not load the server in its iframe within the embed window (8 seconds), or the server blocks framing:

- The server may send `X-Frame-Options` or a `Content-Security-Policy: frame-ancestors` that forbids embedding. The extension cannot and does not bypass this.
- Use **Open in browser tab** — a normal tab is the compatibility authority for origin, authentication, and session behavior.
- Or click **Retry** to reload the embed.

## Page and context capture

### "This page cannot be read. Try selecting text and copying it instead."

The active tab is a restricted page: browser internal pages (`chrome://`, `about:`, `edge://`, and similar), extension stores, privileged PDF viewers, or similar. The browser does not allow content scripts or scripting there. Copy the content manually and use the Clipboard action instead.

### "Page access permission was not granted."

Page reading needs `activeTab` and `scripting`. The request appears at the first page-read action; denying it stops that action only. Retry the action and accept the prompt, or grant the permission from the browser's extension settings.

### "Select some text on the page first." / "This page has no readable content."

The Selection action needs an active text selection on the page before you click it. The Page action found no readable text — common on canvas-only or frame-heavy pages.

### "Clipboard permission was not granted."

The Clipboard action requests `clipboardRead` at click time. Deny is safe; nothing is read. Retry to grant it. Clipboard reading happens only on your click — never automatically.

### "The clipboard is empty."

The clipboard contained no readable text when the action ran. Copy something and try again.

### "Tab permission was not granted."

Tabs and tab-group staging request the `tabs` permission at click time. Retry and accept the prompt.

### "The screenshot is too large to stage."

Visible-tab captures are capped at 8 MiB. Reduce the window size or capture a smaller region of interest. Oversized captures are rejected, not truncated.

### "No browser tabs are available." / "No tab groups are available."

Tab staging reads up to 100 tabs and up to 50 groups. The empty messages mean the query returned nothing (for example, no open browser windows when the action ran). Tab groups use the native group API on Chromium; on Firefox the extension stages a window-based fallback and labels it "window fallback" in the staged text.

## Context tray behavior

### "There is no staged context to export."

**Copy context** exports the items currently in the tray. Stage at least one item first.

### The tray emptied itself

Staged context is memory-only. It is lost when:

- The background service worker restarts (Chromium suspends idle workers; Firefox unloads its background page). This can happen minutes after you stop interacting with the extension.
- The browser, or the extension itself, is reloaded or updated.
- You clicked **Clear unpinned**, or exported successfully (export clears unpinned items).

Pinned items survive "Clear unpinned" and post-export clearing, but **pinned items are also lost on a background restart** — nothing is persisted to disk by design. Copy or use important context before walking away.

### "Unable to copy context." / "Copying is not available in this browser."

Clipboard writing needs `navigator.clipboard.writeText`. Ensure the panel/sidebar surface has focus when copying.

### Clear-all confirmation

Clearing everything requires a second, explicit **Confirm clear all** click. If you expected the tray to clear and it did not, the confirmation step is still pending.

## Composer insertion

### "This Open WebUI page does not support text insertion."

Insertion is capability-gated: the Open WebUI page must advertise the `contextTextInsert` capability over the bridge. Without it, no Insert button is offered, or insertion reports the above. The universal fallback is **Copy context**, then paste into the composer yourself.

### "Image context cannot be inserted as text."

Screenshot items cannot be inserted into the composer. Screenshots stay staged locally; there is no attachment-upload path in this version.

### "Text context exceeds the bridge limit."

Per-insertion text is capped at 32 KiB. Split the item, or copy it to the clipboard instead.

### "Insert text request timed out." / "Host did not acknowledge text insertion."

The page received the insertion event but did not acknowledge it within 5 seconds (or rejected it). Nothing was submitted — insertion never auto-sends. Retry, or use Copy context and paste manually.

### Inserted text but nothing was sent

This is correct behavior. Insertion only places text in the composer input; you review and send the message yourself. The extension has no auto-submit.
